# 飞猪旅行规划 V2.1 产品需求与交互规范

版本：V2.1 / CP-V2.1-2026-10-17。确认日期：2026-10-17（Asia/Shanghai）。项目：D:/aaa飞猪；产品品牌沿用「出游plan」。授权：D-10，本轮用户完整13项要求及其引用的已确认方案。

本文纳入现有 docs 基准，作为本次增量需求的唯一详细正文。功能需求 FR-011/014/017/018/023/028/029 引用本文；其他冻结功能、A「奶油旅行手账」视觉、Hero、GSAP、两住宿分支、城际交通、D-12修订后的三项核心筛选（价格、评分、装修年份）、三家对比、手动酒店确认、核心地点排除决定、携带清单、本地恢复及二次确认重置保持。实现情况另记验收矩阵，规范不代表已实现。

## 1. 产品目标与页面流程

酒店筛选 → 六家候选（可搜索指定酒店）→ 手动选择酒店 → 景点 → 市内交通偏好 → 确认地点数 → 真实路线与逐日编辑 →「完成规划」→ 一页式旅行备忘录。

酒店选择阶段完全取消地图。地图只出现在路线与最终备忘录。路线页主按钮为「完成规划」，不导出文件。备忘录为独立 /plan/memo URL，可返回 /plan/route 编辑。PDF为备忘录附属导出，不再承担终点。

## 2. 酒店候选与搜索（FR-011 / FR-014 / FR-029）

### 2.1 六家候选

桌面宽屏3列×2行，平板2列，手机1列。使用当前真实酒店结果的六个不同ID，保留有事实依据的推荐标签和排序；当前不足六家，显示实际数量与不足说明，禁止复制或伪造补满。更多供应方结果仍可查看或换入候选；对比上限仍是三家。

候选六槽与完整查询结果分别保存，刷新保持用户替换。首次按原有事实推荐优先补足六家；改变展示排序不偷偷覆盖已选槽。更换酒店保留筛选/核心/景点/市内偏好，使旧路线和完成状态失效。

### 2.2 指定酒店搜索

六家候选上方提供「搜索飞猪酒店」，使用目的地和住宿日期查询飞猪已有酒店。按名称搜索不偷偷施加原预算、评分、行政区、品牌限制；说明「指定名称搜索独立于推荐筛选」。结果独立显示，不因搜索返回而改变候选或 selectedHotel。

用户点「加入候选」才打开替换选择对话框，列出当前六家名称；点击具体被替换酒店才提交。取消不改变任何选择。不足六家时可直接补入空位，并反馈；已存在ID不可重复加入。替换候选不等于选中酒店，即使被替换的是已选酒店也保留原住宿决定，直到用户明确选择新酒店；在确认条持续显示当前住宿。

飞猪成功返回空结果时查询高德酒店POI。飞猪服务故障时明确说明服务失败，并由用户选择「改用高德查位置」，不把故障描述为酒店不存在。高德结果标「高德地图位置 · 非飞猪酒店数据」；价格/评分/评论/星级/装修/地铁等未知字段为null / 待核实，无飞猪直链禁用查看并说明，不伪造报价、房型、库存。所有搜索限目的地城市。重名分店必须通过地址/行政区区分，由用户选择，不能自动取第一家。

### 2.3 卡片字段与选择

必有布局字段：图片与来源标签、酒店全名/城市/行政区或地址、认证星级或供应方等级原文、用户评分及分制、评论数、装修/开业年份、地铁距离、重点景点距离与口径、每晚起价和查询时间、来源、查看飞猪、选择这家、对比。

未知字段显示「待核实」，不填0或虚构设施。用户评分5分制与换算综合10分制明确区分，供应方等级不得冒充认证星级。重点景点直线距离仍明确写「直线」，不是道路或预计时间；路线阶段只用高德真实算路。

选中后整卡边框与浅陶土底高亮、勾选、按钮「已选择」并设置 aria-pressed；可随时改选。反馈「已选择：酒店名」，保持约2秒且用 aria-live 宣读。外链点击不改变选择、更不表示预订。

## 3. 统一交互反馈（FR-028）

| 状态 | 规范 | 恢复与无障碍 |
| --- | --- | --- |
| hover | 既有陶土强调边界/背景，主按钮轻抬 | 键盘 focus-visible 同样清楚；手机无需hover才能操作 |
| press | 按下轻沉/轻缩，立即响应 | 不产生布局跳动；减少动态时取消位移 |
| loading | 按钮任务文案、aria-busy、固定尺寸骨架和真实阶段；防重发 | 保留输入/已有选择；可取消；不编造完成百分比 |
| success | 勾选、明确选择态、短反馈和必要的持久状态 | 不只靠颜色；aria-live=polite |
| error | 具体原因、保留内容、明确重试或返回补全 | role=alert；不得在live下静默用mock |

搜索、替换、选择、删除、重新计算、完成、导出均应用同一套状态。连续操作只让最新响应更新对应草稿；切页、换城市、换酒店、重置、取消后旧响应无效。

## 4. 真实路线与粗粒度日程（FR-017）

每天固定「H酒店 → 景点A → 景点B → … → H酒店」，包括返酒店最后一段。空白天显示「酒店休整 / 自由安排」，不虚构往返距离和0分钟导航。

酒店及景点坐标必须核验为高德GCJ-02坐标/POI；酒店飞猪坐标只用于匹配候选，不直接假设为高德坐标。已有高德POI可复用。无法唯一匹配酒店时展示分店候选供用户确认，禁止自动选择第一项。地点解析失败不画假坐标。

按段调用高德 MCP 步行、公交地铁、驾车查询，保留from/to POI、distanceMeters、durationSeconds、mode、线路说明、道路点列（可得时）、source、queriedAt。展示分钟数是高德秒数的单位换算，不是精确出发到达时刻。不得用直线距离×系数、平均速度或AI生成距离/时间。

推荐按查询结果作可解释规则：可步行且实际步行距离≤1.5km、耗时≤25min优先步行；其余按市内偏好选公交/地铁或驾车，有结果时可以混用。公交不可用可推荐有真实结果的驾车，并说明备选原因；驾车标「驾车 / 打车」，耗时不包含叫车等待，不承诺打车价格。没有结果则标该段失败，不填估算。阈值属于可维护实现参数，不是外部服务承诺。

首次分天只作粗粒度分配，早上/中午/下午/晚上；可保留「附近用餐·自由选择」文字，但未选餐厅不是POI，不参与道路算路或地图编号。不做08:32等分钟级日程，不擅自校验开放/预约或承诺未来路况。展示查询时间并提醒出发前核对运营状况。

高德 MCP 若只返回距离/耗时与导航步骤而缺少道路点列：不得将两个POI直连称为实际道路。可显示明确标注的虚线「点位连接示意·非道路轨迹」，同时保留真实距离/耗时；可从同一高德官方路径服务补取点列，但要标注双来源。全段有真实算路数据才能完成规划；草图不等于完整导航地图。

## 5. 每日编辑（FR-018）

删除底部「想调整哪一段/项」自然语言输入区及其主流程。每一天提供「编辑路线/收起编辑」，直接支持拖动排序（含跨天）、键盘上移/下移/移动到某天、删除、更换、添加。

添加/更换使用高德搜索结果供用户明确选择，拒绝重复ID；取消保持原草稿。编辑保存用户顺序和分天，不自动重排。修改后立即使旧段与地图失效，短防抖后自动调用高德；显示「正在重新计算路线…」，成功显示「路线已重新计算」。自动重算与地理重排是不同操作：前者必做、后者不能偷偷改用户顺序。

每次请求带地点/酒店/偏好/日期签名并可取消；旧请求返回不覆盖新编辑。失败保留用户编辑且给重试，不恢复旧线路冒充新路线。查询中禁止完成/导出；可继续编辑，前次请求取消。每日可显示部分成功与失败段，但不得标整趟已完成。

## 6. 一页式旅行备忘录（FR-023 / FR-029）

信息效率70%+视觉30%为设计取向，不是像素面积比例。桌面左侧城市/日期/酒店/每日行程/交通/重要地点，右侧简化地图；手机先摘要后地图再逐日路线，保持一页连续阅读。长行程页面可滚动，不能为塞入一个屏幕缩字、隐藏地点或丢失携带备忘。

右上角「返回编辑｜生成PDF｜完成✓」。返回编辑保留选择与顺序；完成✓只记录本机完成状态并反馈，不触发预订/支付/账号云存储。后续编辑实质行程使完成状态失效，不能复用旧完成快照。

酒店固定H，景点按当前逐日最终顺序全局连续编号（Day2接着Day1）；地图、每日文字、重要地点目录和PDF使用同一编号映射。餐食建议不编号，酒店往返始终H。删改/移动后从当前顺序统一重新编号；全程不能有每天重置或不对应。

地图以真实高德坐标等比例投影：酒店、景点、编号与逐日路线清晰；弱化/不显示普通道路、商业POI和无关标签。使用高德返回点列显示真实轨迹；缺轨迹只用已标注虚线，不能画虚构弯道。提供每日颜色/线型图例、北向与可读地点目录；不能只靠颜色。数据注明「高德地图MCP」及必要的官方路径点列补充来源，注明草图非实时导航。

PDF使用当前备忘录快照，含同一地图、编号、每天往返、交通、来源与查询时间，保留携带清单/备注/勾选。默认紧凑排版，短行程优先一页，长行程自动分页不截断。沿用本地中文字体和浏览器下载；导出失败可重试，不改变草稿、不令服务退出、重复点击防重发。未完成/正在重算/失败路线不导出成已完成规划。

## 7. 状态、迁移和数据边界

新增hotelCandidateIds（最多6个）、selectedHotel.amapPoiId（及address）、routeDraft.schemaVersion=21、hotelAnchor、每一天legs、routeDraft.status=idle/loading/ready/partial/error、error、memoCompletedAt。酒店价格允许null用于地图POI；旧酒店数值字段兼容。

routeDraft 保留原days/stops用于已有草稿迁移；旧路线无真实legs时变idle，提示「旧路线需要高德核实」，保留手动分天/顺序，用户重试计算。刷新时loading变idle，禁止伪装原请求仍在执行。新/旧数据都验证坐标、段数、来源、数值和枚举；缓存是当前浏览器本地数据，不是供应方长期保证。目的地改变清理关联新增字段。地图POI不能满足未核实酒店硬筛选，指定搜索需明确告知独立筛选口径。

供应方与MCP仅服务端访问，Key不进入前端/日志/文档/导出。URL继续执行飞猪域名白名单；图片下载保护、现有Agent/模型/提示词和显式mock规则保留。高德路线不调用AI生成事实。

## 8. 异常与空状态

| 情形 | 用户看到的状态 | 可执行恢复 |
| --- | --- | --- |
| 候选不足6/为0 | 实际数量/无结果，不重复凑数 | 指定搜索、修改条件、现有放宽方案 |
| 指定名飞猪空结果 | 显示高德位置结果及来源；仍为空说明未定位 | 修改关键词/地址，条件与候选不变 |
| 飞猪故障/限流 | 明确查询未完成，不说酒店不存在 | 重试或主动改用高德查位置 |
| 地图酒店无价/无直链 | 待核实、仅位置，查看飞猪不可用 | 用户可只选规划住宿点，另自行核实预订 |
| 重名/分店歧义 | 列地址和行政区，不自动取第一家 | 用户选择确切POI再算路 |
| 高德权限/网络/配额/超时 | 失败原因，保留编辑与选项 | 原地重试，不静默回mock或估算 |
| 某段查不到 | 本段失败，其他段可看；完成禁用并说明 | 调整地点/偏好后自动重算或重试 |
| 缺少道路轨迹 | 虚线、非道路示意标注；真实距离耗时照列 | 出发前打开高德核对 |
| 无景点/所有已删 | 保留空日与添加入口，不报错 | 添加地点；全程无景点不能完成 |
| 中断/刷新/旧草稿 | 恢复顺序，提示需要重新核实 | 重试计算；完成状态无效 |
| PDF字体/下载失败 | 中文错误和重试，草稿不变 | 重新导出/检查下载列表 |
| 存储失败/直接URL缺项 | 现有可见警告/回退并说明 | 补全；不声称已云端保存 |
