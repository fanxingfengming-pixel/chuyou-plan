## 权限与冲突处理

1. 系统 / 开发者约束及用户最新明确指令优先；本项目文档不得覆盖它们。
2. 本体系中的规范按职责引用，不互相复制成多份正文。FZ 冻结索引指向 FR、状态或设计正文；验收矩阵与已知差异只记录事实，不能修改要求。
3. 本体系内部出现实质冲突时，记录到 KNOWN_GAPS；不得自行选较宽松的一条以宣布完成。普通文字纠错无需用户重新批准。
4. docs/v2 保留的接入、图片、PDF和验收资料属于带日期的技术 / 历史证据，不是另一套需求基准；其功能描述与本体系冲突时，以本体系为准。
5. docs/archive、docs/sources、.impeccable/review、旧聊天预览、旧截图、生成缓存和当前源码均不是现行规范。它们可以证明来源或实现状态，不能自动恢复旧版本。
6. 新需求或更改冻结项，必须来自用户明确授权。授权已在本轮给出时直接执行，并同步 FR / FZ、流程、状态、验收及变更记录；不重复询问。
7. 助手提出但未获确认的方案保持“建议 / 待确认”。不能通过时间更新、文档重排、测试通过或改写文件绕开冻结规则。
