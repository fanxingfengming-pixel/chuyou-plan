## 旅行场景与目标用户

面向自行安排旅行、希望减少攻略整理和多平台切换的中文用户，覆盖交通比较、住宿选择、景点筛选和逐日路线规划。用户从初步旅行想法出发，逐步确定选择，并将分散的信息整理为可以继续修改的旅行计划。

## 我做了什么

我开发了一款结合阿里云百炼、FlyAI 与地图服务的旅行规划 Web 应用。

- 一句话解析城市、日期、天数和同行人数，结果可核对、修改和补全；模糊日期保留原意。
- 提供“先选区域”和“先找酒店”两条住宿规划路径，串联城际交通比较、酒店筛选、六槽候选、指定酒店名称搜索与多家对比。
- 景点搜索及按需 AI 推荐经地点服务核实；用户决定是否加入行程。
- 逐日路线支持移动、跨天、添加、删除和替换，编辑后重新查询路段，并保留用户安排的顺序。
- 汇总旅行备忘录、携带清单和路线草图，支持 PDF 导出及同浏览器同来源的本地草稿恢复。

核心设计是明确区分 AI 建议、外部查询结果和用户确认。百炼负责理解与推荐，外部服务提供可核实数据，用户保留最终决定。酒店起价与未知字段如实呈现，查询失败明确提示。

界面采用暖色旅行手账风格，用分步骤流程组织信息，并适配桌面和窄屏浏览器。

## 百炼使用说明（必填）

百炼用于运行时链路，用户使用产品时由服务端实际调用。

- 百炼能力 / 模型：阿里云百炼 Managed Agent；既有接入记录的模型为 `deepseek-v4-flash-0731`，本次发布未重新核验云端控制台配置。
- 调用方式：Node.js 服务端通过百炼 Managed Agent HTTP API 调用，创建 Session、先订阅 SSE 再提交任务，等待本轮完成并校验输出。
- 使用环节与输入输出：自然语言需求 → 城市/日期/天数/人数等结构化字段；真实交通摘要与偏好 → 比较建议；目的地与已选地点 → 候选景点名称并经高德核实；真实酒店候选与筛选条件 → 有效候选 ID；无结果条件 → 调整建议，用户主动选择。
- Skill 名称（如有）：FlyAI，配套酒店及航班查询；服务端使用官方 CLI 执行查询。
- 其他工具 / 技术栈：React、TypeScript、Vite、GSAP、Node.js、高德 MCP、第三方开源 12306 MCP、FlyAI CLI、SQLite 地点资料库、LocalStorage、pdf-lib。

路线距离与耗时来自高德查询。敏感配置保存在本地服务端，不进入前端和公开仓库。

## 踩坑记录（可选）

- Managed Agent 的请求受理不等于完成，需要先订阅 SSE 并等待完成状态。
- 模型输出需要 JSON 校验，酒店推荐 ID 必须属于实际候选集合。
- 酒店资料缺失时保留待核实，不补造设施或房型信息。
- 异步旧响应不能覆盖用户的新选择，错误时保留草稿便于重试。
- 路线编辑后旧路段失效，重新查询时保留用户顺序。
- PDF 需要单独检查中文字体、地图比例、长内容和分页。
