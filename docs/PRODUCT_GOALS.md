# 产品目标

基准：CP-V2-2026-10-17。规范来源见[决定记录](DECISION_LOG.md)。功能正文以[功能需求](FUNCTIONAL_REQUIREMENTS.md)为准。

## 用户与要解决的问题

面向希望用中文逐步确定交通、住宿、景点和行程的独立旅行用户。把自然语言想法转成可修改的旅行信息，再让用户逐项决策；AI / 外部服务提供候选、比较和建议，不能代替确认。

## 已确认产品目标

- 复用 D:/aaa飞猪 的 React + Vite 项目、既有布局和 GSAP 交互；按 D-09 采用用户选定的 A 暖色视觉，提供真正可操作的 Planning Wizard。
- Hero 后进入独立 URL 的规划流程，保留旅行上下文；不再依赖长页锚点和宣传演示。
- 两条住宿分支有实际差异；城际交通在模式之后，酒店与景点确定后再选市内交通。
- 获取可核实的地点、交通和酒店数据，清楚表达未知、模拟、查询报价和供应方边界。
- 路线以酒店与已选景点为基础，D-10提供粗粒度事件顺序、直接编辑与保序自动重算高德实际路段。
- 草稿自动本地恢复，可确认重置；D-10完成规划进入一页式旅行备忘录，PDF作为附属导出。

## 当前范围

自然语言解析与补全、住宿模式、城际交通比较、区域 / 品牌、酒店筛选与搜索、六家候选、独立名称搜索与对比、飞猪外链和手动酒店确认、景点搜索和按需推荐、市内交通、路线与修改、本地草稿、图片复用、PDF 导出。

## 明确不在当前范围

- 账号系统、云端保存、我的行程中心。
- 自建酒店详情页、收藏、订单、支付和实际预订。
- 常驻 Ask FlyAI / 全局 AI 浮窗。
- 分钟级路线和复杂实时调度；道路导航、实时路况、营业时间、预约容量和门票可订性不作为当前路线保证。
- 景点开放时间和门票等可后续补充，不因为旧 V1 演示出现过而自动变成 V2 必须实现项。
- 自驾是原任务的可选项，未接真实道路服务时不能伪装成已支持。

预算模块在 V1 出现过，但未进入已确认的 V2 主流程；不得在整理或普通开发中自动恢复。若未来新增，按新需求处理，详见[已知差异](KNOWN_GAPS.md)。
