# 功能需求

基准：CP-V2-2026-10-17。状态：已确认需求基准；**不代表全部实现或已通过本轮验收**。
FR-001 至 FR-021、FR-024、FR-026 主要来源 D-02；FR-022 来源 D-02 / D-05；FR-023 来源 D-06 及既有 PDF 专项；FR-025 来源 D-04 和既有数据保护。见[来源](DECISION_LOG.md)。

本文件维护需求正文；流程见[USER_FLOWS](USER_FLOWS.md)，字段与失效规则见[STATE_AND_DATA_CONTRACT](STATE_AND_DATA_CONTRACT.md)，逐项完成度见[验收矩阵](ACCEPTANCE_MATRIX.md)。不得因当前接口缺字段、代码未实现或历史测试未覆盖而删除需求。

## FR-001 · 首页与产品入口

- 保留中文品牌“出游plan”、Hero结构和GSAP开场；D-09授权采用用户选定的A「奶油旅行手账」暖色视觉，入口使用明确标注的AI氛围配图。
- 输入自然语言旅行需求，点击“开始规划”进入 /plan/details，不滚动到旧交互演示。
- 开始规划旁提供“全部重置”；重置按 FR-020。
- Hero 后不恢复三块 V1 宣传内容：能力介绍整组、“下一站，想去哪里？”Final CTA、“一次对话，离向往的世界更近。”宣传页。
- 验收：从首页实际提交，URL / 页面切换正确；上述宣传页不参与现行产品流程。

## FR-002 · 需求解析与信息补全

- parseTripPrompt 服务解析出发地、目的地、日期 / 模糊日期、游玩天数、成人数和儿童数。
- 展示解析结果，所有字段可直接修改，缺失字段在此补齐。解析不替用户确认住宿或交通。
- 支持 exact / fuzzy / range；支持“出发日期 + 天数”和“出发日期 + 返程日期”。“11月上旬”“国庆期间”等模糊时间保持模糊，不伪造入住日。
- live 模式使用既有 Agent；解析失败保留用户原文，显示可恢复错误。不得将失败结果冒充解析成功。
- 验收：精确 / 模糊 / 往返日期、人数和缺失信息都能修改与保存；实时报价要求精确日期时再补齐。
- 当前表单数值上限属于实施约束，见状态契约，不是新增的人类冻结数字。

## FR-003 · 住宿模式与多路由

- 两个正式名称为“先选区域”和“先找酒店”，不得改回“先选酒店”。
- 每一步有独立 URL，共享草稿；分支内容实际不同，不共用同一张东京塔演示作为两个流程。
- 模式选定后先进入城际交通，再进入对应区域 / 品牌页面。现行 URL 表见用户流程；原任务允许等价命名，不能退回锚点。
- 验收：两分支分别走通、前进后退保留状态，直接访问缺前置条件的 URL 可回到正确步骤。

## FR-004 · 城际交通比较

- 在住宿模式之后比较高铁 / 火车和飞机；自驾可选，未接真实道路查询不得声称支持真实推荐。
- 服务层包含 searchRailOptions、searchFlightOptions、compareTransportOptions 或等价能力；接入 12306 / FlyAI，明确真实查询、loading 和 error。
- AI / Skill 给建议，由用户选择交通方式；此时不强制选定具体车次或航班。
- 市内交通不放在本步骤。
- 验收：可比较并主动选方式；失败可恢复；实际班次、票价和余票只按查询时刻表述。

## FR-005 · 区域分支

- “热门景点”和“热门商圈”两组可折叠、横向滑动卡片，默认各推荐 3 个。
- 卡片有图片、名称、一句话介绍、类型和行政区；去掉“推荐停留时间”“为什么适合住附近”。
- 用户最多选 3 个位置，并手动指定其中 1 个核心地点。取消核心地点所属选择后，不能保留悬空核心。
- 不喜欢推荐时可自行输入地点，由高德 MCP 确定真实地点、坐标和所属行政区；不得普通网页搜索猜行政区。
- 验收：两组独立可折叠横滑、选择上限与手动核心有效、自定义地点可核实；可靠结果不足时说明缺口，不捏造补齐。

## FR-006 · 酒店品牌偏好

- 酒店分支先问“有偏好的酒店品牌吗？”，品牌按目的地适用范围展示；允许跳过 / 不限。
- D-11：固定展示七个偏好组，不将其称为目的地已有库存。酒店候选和可售情况必须由目的地实际查询确认；海外目的地也不能借演示库存声称品牌可售。
- 品牌仅为前置偏好，不再重复放到后续酒店筛选器。
- D-11：品牌偏好固定为「不限品牌、华住会、希尔顿、万豪、洲际、凯悦、雅高、首旅」，可多选；不限品牌与具体偏好互斥。移除锦江、花筑、格兰云天，不展示品牌图片占位文案。此列表是偏好组，目的地实际库存由后续查询核实，不能声称已发现当地库存。
- 验收：跳过能继续，偏好进入搜索上下文，后续筛选不重复出现品牌项。

## FR-007 · 酒店筛选

- D-12：默认可见三项：每晚价格、综合评分、最近装修年份。删除「距地铁距离」筛选及暂不支持占位；不再传递该筛选、阻拦搜索或写入PDF筛选摘要。旧草稿自动移除这一已删除条件，保留其他偏好、酒店、景点与路线。
- 核心地点和高德行政区解析提供推荐行政区，允许用户选；不要求用户先自行联网查。
- “更多筛选”折叠展示星级、评论数量、用户评分，以及早餐、停车、健身房、洗衣房、亲子、禁烟房等设施条件。
- 品牌遵循 FR-006；控件不一次铺满形成密集 OTA。
- 未知字段显示待核实，启用硬筛选时不把未知候选视作满足。D-08 授权按服务端能力声明暂禁用全局无数据条件并标「暂不支持」；旧草稿保留旧值，用户主动清除后才搜索，不静默放宽。功能保留与数据不足分开记录。
- 验收：条件实际进入搜索与筛选，核心 / 更多层级清楚，未知信息不被伪造。字段不足见 K-001。

## FR-008 · 价格双把手

- 使用可复用 DualRangeSlider 或等价组件。
- 档位覆盖 ≤¥200、¥400、¥600 …… ¥1800、¥2000+；两把手间轨道随拖动伸缩，实时显示数值。
- 支持鼠标拖动；把手不可穿越；靠近时标签错位或合并，不重叠。保留现有键盘与触摸能力。
- 默认按目的地给推荐范围，非默认全范围；无 AI 范围时允许城市预设，但不冒充 AI 实时推荐。
- 验收：拖动、边界、标签与提交值一致。开放端点如何映射供应方检索需要明确，见 K-005，不得悄悄截断“2000+”。

## FR-009 · 装修年份单滑块

- 单把手表达“至少哪一年以后装修”，例如“2022 年及以后”。
- 覆盖不限和原任务 2016–2026 年区间，原“≤2016”字符不改变明确的下限语义；不恢复双把手。
- 不能把 unknown 装修年份当作满足硬性条件。未来年份范围更新属于实现维护，应保留“最低年份”语义。
- 验收：标签、状态字段与过滤方向一致，选择不限不施加年份条件。

## FR-010 · 酒店搜索与异步恢复

- searchHotelsWithFlyAI(payload) 携带目的地、区域位置、核心、推荐 / 已选行政区、品牌、全部筛选及城际交通；日期、出发地、天数和成人儿童一并传递。完整字段见状态契约。
- 状态至少 idle / loading / success / empty / error / timeout，来自真实异步请求；不固定延时伪装成功。
- D-09：使用真实阶段进度条与已等待时间。可测完成数量时显示确定进度；外部等待无百分比时显示活动条。有近期同类耗时样本才给预计范围；样本不足明确说明。阶段由同一次请求的progress/result/error事件驱动，不轮播伪阶段，不承诺准确倒计时。
- timeout 提供继续等待 / 重新搜索 / 放宽条件。empty 给 2–3 套放宽方案，用户自行选，不自动修改条件。
- 保留条件；重试不让旧请求污染新草稿；刷新不能假恢复一个仍在进行的旧网络请求。
- 验收：六态可覆盖；继续等待、重新搜索、条件改变和迟到结果行为符合状态契约。当前软超时 15 秒是实现参数，不是永久冻结值。
- D-08：本地服务状态可检测；中文区分服务中断、供应方失败、额度不足、超时。检测与恢复不自动重复业务请求，输入和草稿保留。
- 放宽建议的具体智能程度与方案适配仍有差异，见 K-003。

## FR-011 · 六家候选与指定酒店搜索

D-10授权：酒店页取消地图，六家不同候选、桌面3×2，独立指定名称搜索，用户选择替换槽；高德POI兜底标注来源、字段未知保持null。推荐与更多结果、排序、三家对比保留。详细正文及验收见 [V2.1第2/3/8/9节](TRAVEL_V2_1_PRODUCT_SPEC.md)。

## FR-012 · 酒店对比

- 最多 3 家；先给简洁结论，再展示并排参数，未知字段保留待核实。
- 顶部结论由 AI / 推荐服务基于这次对比候选与用户偏好产生；不能把不同候选上的旧标签机械复用为已完成 AI 对比。
- 用户可直接在结果卡选择，也可从对比页选择，不强制对比。
- 验收：上限与移除有效，结论对应当前候选，参数可读；三列在手机可横向查看，不导致整页溢出。
- 当前前端 selectHighlights 复用方式不证明独立 AI 对比完成，见 K-003。

## FR-013 · 飞猪外链

- “查看酒店”默认去对应飞猪酒店直链，不新增自己的详情页或收藏。
- 未登录只轻提示“登录后可能使用会员价 / 优惠券”，不阻止跳转；不据此承诺会员价格。
- 仅允许经过校验的供应方 HTTPS 直链；无有效酒店链接显示不可用，不能用首页伪装详情。
- 验收：链接打开与酒店确认完全分离；危险域名、协议和嵌入式凭据被拒绝。

## FR-014 · 酒店明确确认与更换

- 用户手动点击“我已选择这家酒店”后才写 selectedHotel，显示简洁确认状态，再进入景点。
- 点击飞猪外链、回到网页、AI 推荐或打开对比均不自动确认，更不表示已订房。
- 更换酒店保留酒店筛选、核心地点、已选景点和市内交通偏好；清除旧路线，新酒店确定后重新规划。
- 验收：只有手动确认改变选择；更换的保留 / 清除项逐项核对。

## FR-015 · 景点搜索与按需推荐

- 默认用户自行搜索，通过高德 MCP 定位；结果展示名称、类型、地址 / 区域、可得的酒店距离、图片和加入行程。
- 只有用户点“帮我推荐景点”或明确要求推荐时，才基于酒店、核心、天数、自然语言偏好、已加入景点推荐。
- 搜索 / 推荐候选都需手动加入；可撤回，推荐不能变成确认事实。
- 景点数量无硬上限；明显过多给紧凑提醒，仍允许添加。现有提醒阈值是实现参数。
- 开放时间 / 门票 / 官网预约后续补充，不强制第一版实现。
- 验收：首次进入不推荐；主动推荐不自动添加；添加撤回与距离口径有效；过多可继续。

## FR-016 · 市内交通

- 酒店和景点基本确定之后，独立选择公共交通、打车、步行 + 公共交通等偏好。
- 不与城际交通合并，不要求用户在查高铁 / 航班时确定市内方式。
- 验收：选择进入草稿和路线上下文；返回前页不丢失。

## FR-017 · 高德真实路线与粗粒度日程

D-10授权：确认地点数后安排每天酒店→已选景点→酒店；POI/距离/预计时间/交通基于高德MCP真实结果，禁止AI估算。按段合理推荐，保留时段和顺序、不做分钟级日程。缺点列明确标点位示意。详细正文及验收见 [V2.1第4/8/9节](TRAVEL_V2_1_PRODUCT_SPEC.md)。

## FR-018 · 逐日直接编辑与自动重算

D-10授权：删除自然语言调整输入，逐日拖拽/跨天/删除/更换/添加；修改后自动重算高德路线，保留手动顺序与分天，禁止旧响应覆盖。自动算路不等于自动重排。详细正文及验收见 [V2.1第5/8/9节](TRAVEL_V2_1_PRODUCT_SPEC.md)。

## FR-019 · 本地草稿与恢复

- 全页共享统一 tripDraft；返回上一步、跨页和页面卸载不丢状态。
- 存入当前来源 LocalStorage，刷新、关闭后再开自动恢复，不增加“继续上次行程？”确认弹窗。
- 不做账号 / 云端行程保存；不同浏览器、浏览器配置或 5173 / 4173 等来源之间不自动同步。
- 恢复损坏 / 旧版本数据时安全回退；被中断的 loading / timeout 恢复为可重新搜索状态。保存失败应可见，不能假称已保存。
- 验收：新页面、刷新、重启网站后恢复选择与路线；损坏和中断请求可恢复。

## FR-020 · 全部重置

- 首页“开始规划”旁有“全部重置”，必须二次确认。
- 取消不改变草稿，也不误提交开始规划；确认后取消挂起请求、清除 tripDraft，回到初始规划状态。
- 重置只作用于旅行草稿，不借此删除服务端图片缓存、凭据、其他项目或个人数据。
- 验收：取消 / 确认各测，重开页面不恢复已重置行程。

## FR-021 · 修改后的失效规则

- 修改目的地保留出发地、日期和人数等通用信息；清空区域、核心、品牌、行政区、交通推荐与选择、目的地酒店筛选 / 结果 / 对比 / 确认、景点、市内偏好和路线。
- 更换酒店按 FR-014；改变景点、市内偏好或天数应使旧路线失效，不能展示不对应新信息的旧路线。
- 搜索条件或目的地改变后，旧请求迟到结果不得覆盖新草稿。
- 其他未明确确认的日期 / 人数 / 分支切换后确认状态处理见 K-006；不得把代码偶然保留行为直接冻结。
- 验收：按状态契约逐项检查保留 / 清空，不只检查最终界面。

## FR-022 · 图片来源、复用与通用图

- 原区域 / 景点要求优先尝试可靠官网宣传素材；已接入的高德 POI / FlyAI 对应酒店图片是当前真实来源，不称为已取得独立官网授权。
- 同一地点 / 酒店搜索并成功获得图片后沿用，不每次重新搜索或被上游主图变化覆盖；服务重启可复用。
- 网上找不到可靠图时使用统一通用风景图并标“通用风景示意图 · 非实景”，不能冒充指定地点或酒店照片。
- 临时网络失败可临时兜底，后续允许重试；确认无图可以缓存。品牌暂无素材可占位。
- 图片直接服务端获取与缓存，不为图片检索新增模型调用；不把其他 Agent、API、存储或带宽消耗称作免费。
- 验收：对应实体、来源标签、同 ID 复用、重启、无图、临时失败与前端加载失败分别验证。官网素材与授权未全量完成，见 K-004。

## FR-023 · 完成规划、旅行备忘录与PDF

D-10授权：路线主按钮「完成规划」进入一页式备忘录；右上角「返回编辑｜生成PDF｜完成✓」，PDF为附属导出。真实坐标草图、H酒店、跨天全局连续景点编号与文字/PDF一致，保留携带清单及备注；本地中文分页/快照/错误重试保护沿用。详细正文及验收见 [V2.1第6/7/8/9节](TRAVEL_V2_1_PRODUCT_SPEC.md)。

## FR-024 · AI 出现位置与范围

- AI 仅在需求解析、交通比较、酒店搜索 / 推荐与对比、无结果放宽建议、用户主动景点推荐、路线相关的具体操作等相应页面出现。
- 不新增常驻 Ask FlyAI / 全局对话浮窗。
- 账号、云端行程中心、自建酒店详情、收藏、订单、支付不属于当前范围；预算不得凭 V1 文件自动恢复。
- 验收：全流程不出现额外常驻对话入口、账号或交易闭环；每个推荐与确认状态明确。

## FR-025 · 真实服务与显式模拟

- 沿用现有百炼 Managed Agent，不在普通开发中更换模型、提示词、工具包或云端环境。
- 地点 / 行政区高德 MCP、铁路 12306 MCP、酒店 / 航班 FlyAI CLI、飞猪供应方直链经服务端接入；服务和 UI 分离。
- live 是真实查询路径；模拟目录仅用于显式离线模式和测试，不在组件内写死真实候选，不在失败时静默退回 mock。
- 未知字段、报价口径、人数 / 房间参数限制、安全外链与凭据隔离遵循状态契约和开发标准。
- 验收：可追踪真实 / 模拟来源；失败明确；本地测试不冒充真实供应方、支付或商业上线验收。

## FR-026 · 视觉、动效与可操作性

- 按 D-09 采用 A「奶油旅行手账」暖色：奶油底、纸张表面、陶土重点；保留克制大字号、摄影式 Hero 结构和 GSAP 开场，保持清晰的操作流程。

## FR-028 · 缺项与操作反馈

- 必填项缺失时继续按钮可触发校验，显示具体缺项并定位问题；请求期间防重复提交。直接访问后续URL返回正确步骤且说明原因，完成后移除过期提醒。
- 可跳过的品牌偏好保持可跳过；未支持筛选控件仍禁用。点击搜索可解释阻塞原因，但不得发出不受支持的查询。
- 选择、移除、达到上限、加载失败、重试和保存异常有明确反馈；本地保存保留现有错误说明。
